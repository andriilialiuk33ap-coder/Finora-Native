# Finami 5.2 Intelligence — build 29

База: Finami 5.1.3 (build 28). Bundle ID `ua.finora.personal` і файл фінансової бази збережено. Нові поля бази/налаштувань опціональні. Перед встановленням експортуйте JSON або зашифровану копію.

## Нові функції
- Ще → Виявлення підписок: не менше трьох платежів з однаковим нормалізованим продавцем, рахунком і валютою; щомісячні інтервали 25–35 днів, щотижневі 6–8 днів лише для категорії підписок. Попередні два тарифи мають бути близькими, остання сума може змінитися не більше ніж на 30%. Пропозиція створює лише графік після підтвердження, не нову витрату. Пропущені пропозиції можна відновити. Загальні Apple/Google-платежі не трактуються як конкретна підписка. Результат є евристикою, не гарантованим визначенням договору.
- Розумна звірка: порівнює доступний залишок на дату/час останнього повідомлення з історією операцій і кредитним лімітом, окремо показує пізніші рухи. Не змінює баланс автоматично. Якщо початковий баланс, ліміт, блокування/холди або час повідомлення відрізняються, результат може бути неточним. Для виправлення пропонує імпорт виписки або уточнення операцій.
- Фінансовий помічник: прострочення, заплановані оплати, оцінка вільних гривневих власних коштів після резерву й відомих платежів, пропозиції підписок та можливе зростання їх вартості. Прогноз локальний, без гарантій; інші валюти окремо. Не здійснює платежі.
- Локальна категоризація: словник відомих продавців, нормалізація назви, пріоритет вивченого правила, конфлікт правил не вгадується. Категорія «Без категорії» не повинна перешкоджати запису однозначної покупки. Сума, рахунок, тип руху та ризик дубліката все ще потребують уточнення, якщо неоднозначні. Розпізнавання не є моделлю ШІ і не гарантує категорію для кожного продавця.
- Головна: розстрочки з назвами й залишком; підписки з назвами й сумами; регулярні платежі включають розстрочки та підписки без повторного створення. Кількість рядків, сума, назви, дата — у налаштуваннях блоку. Загальна сума регулярних платежів — неоплачене за графіком вибраного місяця, майбутні повтори є прогнозом. Окремо показуються прострочення в календарі. Новий блок «Календар платежів» можна увімкнути через налаштування головної. Повноекранний календар має фільтри типу/стану, переходи між місяцями, фактичні записи оплачень через спільний механізм і прогноз майбутніх повторів. Українські назви місяців для найближчих платежів та календаря.
- Звіти: «Усі надходження» окремо від доходів, включно з поверненнями, переказами, поповненнями та кредитними надходженнями. Порівняння цілих періодів або однакової кількості календарних днів; кеш порівняння скидається після змін операцій. Попередній перемикач доходів збережено.
- Меню: імпорт виписки та скриншотів доступний через єдиний центр імпорту, прибрано дублюючі посилання з «Ще». Автоматизація починається з імпорту шаблону, ручні параметри нижче.

## Віджети, підпис IPA і приватність
У стандартний проєкт додано WidgetKit extension `ua.finora.personal.widgets`. Три віджети: власні кошти, найближчий платіж (відкриває календар), швидка витрата (відкриває форму). Вони не створюють операції без підтвердження. Встановлення та реєстрація розширення залежать від iLoader/SideStore і підпису.

Стандартний XcodeGen `project.yml` не запитує App Groups, щоб не робити підпис групи обов'язковим для звичайної IPA. Віджети без App Groups — швидкі переходи, **без фінансових сум**. Для фінансових сум потрібна спільна зареєстрована група `group.ua.finora.personal` у provisioning profiles застосунку й розширення. Опційна конфігурація: `xcodegen generate --spec project-widget-groups.yml`, потім налаштувати підпис обох targets в Apple Developer. Це не створює entitlement на стороні Apple і не обходить обмеження безкоштовного підпису. Опційний профіль не перевірено в Xcode.

Після підпису з App Groups: Ще → Віджети iPhone → Дозволити суми у віджетах. За замовчуванням вимкнено. Передається лише мінімальна зведена копія (сума власних видимих включених UAH рахунків, сума/валюта/дата найближчого платежу), не фінансова база. Дані зникають при блокуванні Face ID або приховуванні сум, знімок старше 24 годин не використовується. WidgetKit може затримувати оновлення, тому попередній намальований віджет може деякий час залишатися видимим.

## Що не завершено
- Справжній імпорт iCloud-команди і тригер банківського сповіщення потребують перевірки на реальному iPhone; URL збережено, веб не повернув вміст. Немає стандартного Apple Pay iCloud-шаблону. iOS контролює підтвердження імпорту/активацію. Повний фоновий запис під замком не додано.
- Часткове/дострокове погашення через спільну форму та узгоджене скасування пов'язаних платежів не перероблено у цій версії. Не виконується автоматичне ретроспективне зв'язування старих оплат чи зміна їх класифікації. Графік існуючих договорів використовує поточні моделі. Не здійснено перехід на SQLite.
- Публікація у GitHub, Xcode-компіляція, XCUITest, реальний WidgetKit та фізичний iPhone не перевірені у Linux. GitHub Actions тепер також перевіряє наявність вкладеного `.appex` і URL scheme. Два нові XCUITest сценарії: виявлення підписки та календар. Шифрування запускається на macOS.

## Установка
Завантажити повний архів у корінь клонованого репозиторію через GitHub Desktop, зберігаючи `.github`, `Config`, `WidgetShared`, `FinamiWidgets` та `.git` локального репозиторію. Commit → Push. Запустити новий `Test Finami on iOS Simulator` для нового SHA (не повторювати старий запуск). Після результату надіслати архів журналів. Для збірки IPA — ручний запуск із `build_ipa`.
