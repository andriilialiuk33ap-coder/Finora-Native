# Finami 6.1.1 Next · Balance Repair (build 43)

## Зміни
- Єдиний `CardPosition` для власних коштів, боргу, доступних коштів та невикористаного кредитного ліміту. Головна, картки й загальна сума кредиту використовують один розрахунок. Це не означає, що історія старих імпортів уже виправлена.
- Повторний імпорт не створює дубль точного банківського ключа, який належить іншому рахунку. Якщо виписка однозначно ідентифікує рахунок, пропонується перенесення однозначних записів із попереднім переглядом впливу на залишки. Зміни тільки за підтвердженням; захищені платежі, повернення, групові перекази, невизначені ключі й пов'язані валютні записи не переносяться автоматично. Старий тип/категорія, сума та дата зберігаються; перевір їх після перенесення. Якщо історія змінилася після підтвердження, імпорт необхідно перевірити знову.
- У майстрі «Розумна звірка рахунків» доступні контрольний чистий баланс на дату, введення власних коштів/використаного кредиту, або явно підтверджена оцінка з доступних коштів. Нуль доступного залишку не визначає чистий борг. Оціночна точка позначається у рахунку. Старі імпорти до контрольної дати не змінюють поточний залишок, але зберігаються в історії. Дані після дати змінюють баланс як звичайні операції. Не використовуйте доступні кошти як точний обліковий баланс, якщо є холди.
- Ручна звірка в редакторі рахунку теж встановлює контрольну дату. Суми не підміняються фіктивними доходами/витратами.
- Джерела операцій показано в журналі й редакторі, для старих записів без метаданих — «Ручний / невідоме джерело». Центр звірки має прямі переходи до валютної звірки, схожих операцій і вхідних подій автоматизації.
- Останнє підтверджене перенесення під час імпорту можна скасувати в майстрі звірки, якщо операції з того часу не змінювалися. Скасування відновить весь стан операцій перед таким імпортом; не виконує окреме скасування ручного контрольного балансу.

## Перевірка на iPhone
1. Зробити резервну копію перед оновленням. Встановити повний код через GitHub Actions.
2. Повторно імпортувати актуальну виписку дебетового рахунку, потім кредитного, обравши правильні рахунки. Перевірити запропоноване перенесення, можливі дублікати та нові рядки. Не видаляти реальні надходження.
3. Якщо валютний переказ дублює реальні надходження, у «Ще → Розумна звірка рахунків → Перенести записи або об’єднати обмін» обрати «Об’єднати валютний переказ». Вибрати всі фактичні частини обміну. Ручну різницю курсу виключати лише якщо підтверджено, що вона вже врахована у фактичній сумі, а не окрема комісія.
4. Порівняти фінансові показники на одну дату. За необхідності ввести контрольну точку у «Ввести контрольний баланс банку». Для кредитного рахунку використати власні кошти та фактичний використаний кредит. Для дебетового — чистий баланс або явно позначену оцінку з доступного залишку. Перевірити, що наступна операція змінює залишок один раз.
5. Надіслати журнал Test Finami on iOS Simulator, журнал Build IPA, якщо збірка не пройшла, та нову резервну копію після звірки, якщо залишилася різниця.

## Межі
- Finami не підключається до банківських балансів у реальному часі. Не визначає причину всіх холдів, незавершених платежів або відсутніх рядків самостійно.
- Ключі зі старої версії парсера можуть відрізнятися; невизначені збіги потребують ручної перевірки. Немає автоматичного видалення справжніх транзакцій, автопідміни залишків чи міграції особистої бази.
- Локальні тести Foundation та синтаксис Swift не замінюють збірку Xcode, PDFKit, UI та тестування на iPhone. CryptoKit/CommonCrypto перевіряються на macOS.
