# Finami 6.4.21 / Build 69 — стабілізація

## Поточний стан
Build 68: за наданим GitHub Actions журналом 27/29 UI-тестів; дві помилки — збереження OCR ПУМБ і відкриття вхідного платежу. Build 69: явна валідація та підтвердження біля кнопки збереження, єдиний sheet для перегляду вхідних та звичайних операцій, діагностика UI-тестів. Причину блокування збереження або конфлікту sheet не можна остаточно підтвердити без нового прогону Xcode. Не вимикати захист від дублювання та перевірки фінансових даних.

## Матриця приймання (робочий план, не звіт про завершення)
Для кожної функції зареєструвати ID, екран, початкові дані, дію, очікуваний стан, результат після перезапуску, пов’язані екрани, автоматичний тест, ручну перевірку та статус. Статуси: не перевірено / пройдено / збій / заблоковано. Не вважати відкриття екрана доказом роботи дії.

| Область | Обов’язкові сценарії | Інваріанти |
|---|---|---|
| Рахунки та баланс | створення, редагування, звірка, архів, кредит, мультивалюта | баланс узгоджений з історією; власні кошти й кредит окремо |
| Операції | створення, зміна суми/дати/категорії, видалення, групові зміни, повернення, компенсації, перекази | суми в мінімальних одиницях; без подвійного обліку; збереження після перезапуску |

## Ризики для наступного аудиту
- Store вже має єдину БД, атомарний запис і кеші. Перевірити всі залежності кешів після зміни рахунку, категорії, налаштувань і відновлення; не переписувати ядро без регресій.
- Метадані OCR ПУМБ частково залишаються в чернетці; перевірити повний життєвий цикл графіка.
- Повторне натискання вкладки: перевірити захист незбережених чернеток.
- Simulator workflow створює IPA тільки після успіху, окремий build.yml запускає лише фінансові тести, а не повний UI-набір. Для стабільних релізів використовувати Simulator; надалі уніфікувати release gate.
- Додати тести міграції з попередніх версій та перехресних сценаріїв з незалежними очікуваннями; не покладатися на кількість PASS.
- Обмеження iOS: сторонні push/SMS не доступні застосунку довільно; реальні дозволи, Shortcuts, фон, віджети і нагадування перевіряти на iPhone.

## Критерії стабільного релізу
Усі заявлені сценарії пройдені або обмеження явно документовано; повні регресії та Xcode UI-тести зелені; жодного критичного дефекту фінансів/втрати даних; ручна перевірка на iPhone; відновлення резервної копії перевірено; IPA відповідає протестованому commit. Не обіцяти відсутність усіх можливих дефектів.
