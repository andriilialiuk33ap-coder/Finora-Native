# Build 78 — Release Candidate: накопичувальна стабілізація після Build 71

Виконано одним пакетом, без штучного випуску семи проміжних версій. Нижче саме зміни коду та межі приймання, а не підтвердження безпомилковості всього застосунку.

## 72 — Financial Consistency II

`FinamiDatabaseSafety` перевіряє обсяг і знаки minor units, підтримувані діапазони, сукупну межу, скінченність дат та ключові ID. Викликається на старті до міграції/публікації, перед звичайною мутацією та імпортом, під час відновлення. Чинний більш суворий валідатор restore збережено; пошук рахунків у ньому переведено на словник. Чинні перевірки компенсацій/зв’язків оплат/групових переказів не вилучено. Політика: зупинити запис і зберегти оригінал, не виправляти суми автоматично. За межами: повний аудит усіх формул і метаданих реального банківського графіка, міграція на повністю деталізований графік.

## 73 — Performance Engine

Відомий запис виключно appearance sidecar не перебудовує індекси і не порівнює весь масив операцій у didSet. Загальна ревізія все одно змінюється для захисту фонових імпортів. Інші записи зберігають консервативну інвалідацію. Валідатор має O(n) витрати; тест 100000 рядків вимірює лише час на тестовому хості. Instruments на iPhone, загальний ChangeSet і повністю фонова послідовна черга запису ще не реалізовані/не підтверджені.

## 74 — Automation Reliability

Періодичне читання файлів на активному екрані та BGAppRefresh перенесені поза main actor. Застосування результату залишається серіалізованим у Store, перевіряє ревізію та скасування. Ручне оновлення залишається синхронним. UUID і суми перевіряються до запису та при читанні, файли понад 64 KiB та symlink ізолюються; пошкоджені файли не видаляються. Невдалий commit не видаляє подію. Розташування «Вхідні операції» у вкладці «Операції» не змінено. Таймер 6/12 с залишено як резервний механізм, бо немає гарантій подієвого виклику iOS у всіх сценаріях. Apple Pay, Shortcuts і фонова доставка на реальному пристрої потребують перевірки.

## 75 — Code Quality

DEBUG-фікстури винесено з Store. README скорочено, нотатки та старі журнали переміщено в docs/history, додано CHANGELOG та тематичний каталог тестів. Імена production-файлів і тестових скриптів залишено, щоб не ламати залежні сценарії. Повний SwiftFormat/рефакторинг довгих SwiftUI-виразів відкладено до компіляції Apple SDK. Попередження компілятора Build 71 залишено.

## 76 — Functional Audit

Сценарії див. матрицю нижче. Додано перевірку фінансових меж у Diagnostics (не змінює базу) та її UI assertion. Додано UI-тест відкриття прихованої підписки через глобальний пошук, перевірки маски суми та історії. Не вважати відкриття екрану повним тестом функціоналу. Існуючі 29 UI-тестів збережено; разом 30.

## 77 — Security & Privacy

Суми прихованої підписки маскуються у спільній картці, деталях і історії незалежно від джерела переходу; у віджет не передається payload найближчого прихованого платежу. Історія також враховує прихований рахунок або напрямок переказу. Збережено PBKDF2 600000 + AES-GCM, захист файлів, quarantine, попередні правила приватності. Редактори за явним відкриттям залишаються доступними, глобальна приватність не є криптографічною ізоляцією. Повний аудит доступності, скриншотів, усіх експортів і реального App Group ще не завершений.

## 78 — Release Candidate

`simulator.yml`: після `xcodebuild test-without-building` перевірити JSON summary з xcresulttool, очікувану кількість тестових методів, нуль failed/skipped. Якщо формат summary не підтримується — gate закритий, не створювати IPA. Обидва workflows використовують цей шлях. Додаток і віджет мають Build 78, bundle ID, App Group, шляхи та XcodeGen targets не змінено. Не вважати кандидат стабільним до одного зеленого Apple CI прогону на цьому коміті.
