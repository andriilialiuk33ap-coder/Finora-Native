# Build 80 — Installment Engine

База: Build 79. Версія 6.4.32. Проміжна збірка, не підтверджений реліз iOS.

## Модель
- `importedSchedule` — довідкові OCR-рядки, в т.ч. явно розпізнані нульові внески; не створюють проводок.
- `confirmedSchedule` — опційний список позитивних несплачених внесків. `nil` означає старий розрахунковий графік; `[]` — закритий підтверджений договір. Активується лише за явної згоди користувача, збігу першої дати і точної суми залишку. Користувач перевіряє статус усіх внесків. Історичні рядки до вибраної дати не використовуються як проводки.
- Збережений договір з підтвердженим графіком перевіряється спільним валідатором. Додані optional-поля в історії скасування оплати; старий JSON декодується без автоматичної активації графіків.
- При частковій оплаті зменшується перший рядок, дата не змінюється. Погашення рядка переводить на наступну фактичну дату. Повне погашення закриває всі рядки. Дострокова часткова оплата понад перший внесок, але менша за залишок, блокується до оновлення графіка: невідомо як банк розподілить її.
- Відв’язування останньої оплати відновлює графік і не видаляє фактичну операцію. Застарілий запит відхиляється. Створення або оновлення договору з OCR не змінює баланс, кредитний ліміт чи історію операцій.

## Підключення
`FinamiPayment.occurrences` використовується для календаря і календарного експорту. Місячний план використовує підтверджені дати і суми; прогноз окремо враховує прострочені внески. Головна, віджети й список найближчих платежів споживають той самий `upcomingPayments`. Нульові рядки видимі у довідковому графіку, але не є платіжними подіями. Додано пояснення, що регулярний внесок у підтвердженому графіку довідковий. Оновлення договору не може мовчки замінити підтверджений графік; користувач обирає новий або явно вимикає старий. Повторний точний скриншот архівного договору вимагає спочатку відновити договір. При редагуванні параметрів з активним графіком потрібно вимкнути його або імпортувати оновлений.

## Межі та наступний етап
- Vision, Xcode, реальний інтерфейс, WidgetKit, CryptoKit, продуктивність на iPhone не перевірені.
- Неповні або суперечливі OCR-рядки не стають активним графіком автоматично. Для підтвердження потрібні фактичні дати й суми несплачених внесків. Окремі статуси банку, комісія, перший внесок, повний детектор графіків Monobank/ПриватБанку, ширший рефакторинг OCR і багатовалютні розстрочки не реалізовані цим етапом.
- Перед оновленням зберегти повну резервну копію. Старі збірки можуть прочитати JSON, але не знають `confirmedSchedule`, тому повернення після активації графіка без відновлення попередньої копії не рекомендується.
- Bundle ID, App Group, локальні шляхи, шифрування, Aurora Balance та Fusion Crystal не змінювалися.
